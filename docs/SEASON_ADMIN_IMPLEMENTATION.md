## Durable plan and data contract

Add a draft target season state while retaining existing active/archived rows. Maintain exactly one active season and at most one open transition for it. A Coach-only `seasonTransitionPlans` parent stores source/target season IDs, explicit numeric competition year, target name/dates, actor, stable actor-scoped retry key, revision/fingerprint, state (`draft|reviewing|draining|applying|verifying|failed|complete`), last error, progress and final confirmation hash. Child rows hold each source student ID, returning/departing choice, optional target student ID, reviewed profile/link copy choices, financial source and debt fingerprints, and per-source/per-charge dispositions with required reasons and external refund evidence. Each personal-payment-to-team decision records the exact source and amount, Coach actor, date/time and reason; no family-authorization field or gate is required. Use indexed child pages and bounded job steps; do not put a roster or ledger in one plan document. Record every decision's actor/time/revision. Freeze the complete reviewed decision set when application starts; later edits create a new review revision, never silently change an applying plan.

Each financial movement has a stable operation identity and paired old/new evidence. Carry a remaining fundraiser source out of the old profile exactly once and in to the mapped new profile as fundraising with its root origin/fundraiser lineage; carry personal funds only as personal. Preserve raised-gross attribution on the old source and exclude incoming carryover from new gross Raised. For debt carry, close/cancel only the selected old outstanding amount and create one target opening charge linked to `originChargeId`; the two sides and idempotency marker commit together. Write-off is an explicit reasoned cancellation/adjustment, never deletion. Held departing balances remain on archived historical records and are excluded from new-season available credit. Recorded team moves preserve their source kind and must not imply bank accounting. A Coach-reviewed personal-payment-to-team move needs an explicit source/amount disposition and append-only Coach actor, time, reason and payment-lineage evidence, but no family-authorization gate. This action is never labeled an offline cash refund. A special family refund request receives a separate Coach decision; if approved, an actual personal cash/check payout uses the existing method/reference/date workflow and cannot consume a fundraiser source. Partial/mixed-source residuals require source-level decisions; one broad student-level label cannot erase provenance.

All account/financial/event/attendance writers must observe a common closing lock and deny or defer conflicting source-season writes. Preserve permission to revoke an account during the lock. Background work uses durable one-student (or smaller measured) transactions with progress and idempotent replay; a job failure leaves the old season active, new season draft, and committed steps visible. A retry resumes from recorded state after revalidation. No user-facing success or new active season follows merely from scheduling the job.

## Coach workflow and API surfaces

1. **New season.** Coach enters unique name, explicit competition year and dates. Server validates chronology/name collisions and creates a draft, not a second active season. The separate kickoff helper (`convex/lib/seasonCalendar.ts`) can mark a verified competition-year build boundary; an unknown year stays unavailable pending official verification. Phase reporting groups sessions by scheduled start at the verified kickoff boundary. Outreach and Build titles classify sessions case-insensitively; Build weekday/Saturday uses the Chicago calendar date, with Sunday held separately.
2. **Returning students.** Paginate the current-season roster. The Coach explicitly marks return/depart for each row and reviews which contact/profile/Parent-link fields carry to a new profile. Resolve same-person/account collisions before proceeding. Show a stable mapping preview; do not duplicate appUsers or Google identity.
3. **Archive departing.** Show each departing student, linked account/access consequence, existing holds and retained historical records. Require an explicit archival choice and reason where the account is actually archived. An actual active→inactive account archive writes a new `archivedAt` at that transition; an already-inactive no-op preserves its existing timestamp. Reactivation preserves prior archive history, and a later actual rearchive writes the new timestamp that starts the latest five-year clock. Do not use old-season closure alone to start/restart that clock. Parent links to old records remain historical and do not grant new-season access.
4. **Balances.** Show source-separated personal/fundraising available balances, known/unknown Raised, per-charge unpaid amounts, prior payouts/transfers and any unresolved financial job. Require each outstanding charge's carry or write-off decision (write-off reason). Require each departing residual source's explicit hold/team choice with reason and exact source amount; no team transfer happens automatically on archive. Display the normally nonrefundable rule and a separate path for a special family refund request and Coach approval. An approved actual personal refund uses the separate payout record; never label a team move as a refund. Flag incompatible selections before leaving this step. Returning carry-in is a reviewed source-by-source choice, never an inferred combined balance. Display incomplete/legacy provenance and block application until resolved.
5. **Retain / reset.** Review optional copying of requirement definitions and approved wording into **new versions**; do not copy event participation, room/driver assignments, attendance, health/medication authorization, signed submissions, permission coverage, completion evidence or old-season financial summaries. Existing old evidence remains immutable and queryable by authorized historical scope. New seasonal health/contact fields need explicit review; unknown values stay unknown.
6. **Confirm.** Present an exact summary of roster mappings, archives, every debt/fund disposition, source movement totals, held/unresolved items, copy/reset choices and cutover readiness. Link directly back to each missing decision; require typing the target name and current plan revision. Commit starts the durable job. Before final activation verify all expected child rows completed, old/new source and charge paired totals conserve cents, lineage/revisions match, no open conflicting Timeclock work, no incompatible active financial job, and no unprocessed roster mapping. Switch source to archived and target to active in one final transaction, append audit, then expose completion. A failed verification remains retryable/visible and does not label either season falsely closed.

Coach read APIs: bounded active-season preview, plan/decision pages, progress/errors, and paginated archived-season summaries/detail/history with restricted fields. Coach mutations: create/update/review decisions, freeze/commit/retry, and explicit historical correction operations. All take auth-derived actor; every write uses strict validators, expected revision/fingerprint, reason where required and stable retry identity. Travel Lead, Mentor, Student and Parent cannot mutate a transition or open historical financial/health records.

## Implemented historical correction mode and held cases

An archived season opens read-only. Coach clicks **Make a correction**, sees the prototype warning, then enters a short-lived, actor/season-scoped correction mode; the mode is not a global `activeSeason()` bypass. Every correction previews exact record IDs, current revision, before/after, source effects and required reason, and commits through the same domain conservation rules with an append-only correction/audit entry. A historical account balance cannot be overwritten by setting a number: identify the underlying charge, payment, fundraiser, transfer or source and adjust it causally. Unsupported legacy provenance, spent fundraising, later-season linked carryover or stale snapshots hold for a dedicated reviewed resolution. Corrections must re-evaluate downstream carried sources and summaries before completion; if safe propagation cannot be proved, fail closed rather than changing only the old display. Historical roster/attendance corrections likewise preserve original evidence and restricted access. Signed permission snapshots and original receipts are never rewritten.
